# Font Awesome Configuration

Detected by the Font Awesome agent tools. Commit this file so the whole team benefits.

## Integration

- **Method:** Kit embed, Web Fonts + CSS (`<link rel="stylesheet">` in `app/layout.tsx`) — not the SVG+JS auto-replacer, since that mutates the DOM outside React's control.
- **Version:** 6.7.2
- **License:** Pro
- **Kit ID:** `95881adc33`
- **CDN URL:** `https://kit.fontawesome.com/95881adc33.css`
- **Families:** classic (brands, light, regular, solid, thin), duotone (light, regular, solid, thin), sharp (light, regular, solid, thin), sharp-duotone (light, regular, solid, thin)

## Defaults

- **Style:** solid
- **Family:** classic

## Import Pattern

No npm package — icons render via plain elements styled by the Kit's CSS, wrapped in this project's existing per-icon component pattern:

```tsx
// components/patterns/icons.tsx
function fa(style: "solid" | "regular", name: string, className?: string) {
  return <i className={["fa-" + style, "fa-" + name, className].filter(Boolean).join(" ")} aria-hidden="true" />;
}

export function BullhornIcon({ className }: IconProps) {
  return fa("solid", "bullhorn", className);
}
```

Callers are unchanged from before the migration — `import { BullhornIcon } from "../../icons"; <BullhornIcon className={styles.foo} />` — only the internals of `icons.tsx` changed (hand-drawn SVGs → real Kit glyphs). This kept every consumer across the app (Nav, dashboard sections, the Olivia panel, buttons) working without a single call-site edit.

## Conventions

- **All ~39 icons in `components/patterns/icons.tsx` are migrated** to this Kit as of this entry. None are hand-drawn SVGs anymore.
- **Sizing changed from `width`/`height` to `font-size`.** These are font glyphs now, not SVGs — every CSS rule that used to size an icon via `X svg { width: Npx; height: Npx }` (or a class applied straight to the icon element) was converted to `X i { font-size: Npx; line-height: 1; }`. If you add a new icon usage, size it the same way: set `font-size` on the icon element or its wrapper, not `width`/`height`. `components/ui/Button.module.css`'s `.icon`/`.iconOnly .icon` wrapper already did this correctly (it always set both) and needed no change.
- A few names were confirmed against Figma's own export rather than guessed, where a ligature failed to render and fell back to literal glyph text: `table-layout` ("This page" scope), `clipboard-check` (audit topic), `bullhorn`/`file-pdf` (component names). `sack-dollar` is a judgment call for Figma's "Financials" concept, which isn't a real FA icon name.
- Verify any *new* icon actually exists in this Kit's subset before wiring it up (`fa kit icon --kit-token 95881adc33 <name>`, or the `fetch-kit.py` script if `fa` isn't authenticated) — a Kit only ships a subset of the full library.
